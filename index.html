TC-01 · About

Testing is exploration

My instinct is to question assumptions. While everyone else thinks about what should happen, I map out what could go wrong — and document it clearly enough that it actually gets fixed.

I work the QA process end-to-end: analyzing requirements, designing structured test cases, executing manual and exploratory passes, and logging defects with full reproducibility — severity, priority, steps, expected vs. actual.

Through Leapfrog Connect's QA Foundations training I've practiced this on real platforms, including API testing with Postman and UI automation with Cypress. And as a computer science student, I understand how software is built — so I know where the likely failure points are before I even open the app.
